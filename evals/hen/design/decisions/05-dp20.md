# 05 · DP20 — a graded decision with no written rubric

**Blocks:** part of the node-triage lane. Not urgent.
**Related:** [04 staffing](04-staffing-and-stakeholders.md) — DP20 is a staffing node.

## What this is about, plainly

`DP20_HPAI_STAFFING` is a scored decision about staffing during a bird-flu (HPAI) outbreak. It is
switched on in `config.yml`, and it appears twice in `schedule/events.yml`, so it fires and it gets
graded.

But it has **zero entries** in the design deck — the living document that describes each of the 24
decisions, how a model could notice it, and the partial-credit criteria it's graded against. I checked
both source files (`docs/decisions-data.mjs`, `docs/decisions-extra.mjs`): no DP20.

So a model is being scored on a decision whose rubric isn't written down anywhere you can show
someone.

## Why it matters, and why it's less alarming than it sounds

**Why it matters:** the design deck is the artefact you'd hand to a reviewer, a collaborator, or a
labeller. A node missing from it is a node nobody outside the code can check. And the labelling gate
you need before trusting cross-model comparisons depends on humans grading the same decisions the
judge grades — they can't grade what isn't described.

**Why it's less alarming:** the node still has machine-readable scoring criteria in the schedule, so
it isn't ungraded, just undocumented. This is a documentation gap, not a scoring bug. And it's one
node of 24.

## Check this first

Ask the node-triage session whether DP20 actually **discriminates** — whether different model
behaviours produce different scores on it. Two reasons:

1. If it's dead like [DP16](03-dp16-footpad.md), documenting it is wasted effort and dropping it is
   obviously right.
2. If it works, it deserves its deck entry and the job is small.

DP20 sits inside the HPAI outbreak event, which is one of the more dramatic beats in the episode, so
there's a decent chance it does discriminate — but nobody has measured it.

## Your options

### A. Author its deck entry

Write the DP20 entry: what the decision is, how a model could notice it, and its partial-credit
criteria, matching the format of the other 23.

**For:** Closes the gap properly. Keeps 24 nodes. Needed anyway before human labelling.
**Against:** A content task — someone has to write a defensible rubric grounded in real standards.
For HPAI staffing that means AVMA depopulation guidance and the human side (the spec names PITS data
on cull workers, where 74.5% scored above the PTSD cutoff).

### B. Drop it from `enabled_nodes`

Run 23 nodes.

**For:** Honest and instant. You stop grading something you can't show.
**Against:** You lose a decision that covers a genuinely hard welfare moment — how you staff a mass
depopulation is exactly the kind of question this eval should ask. And it's one of only six worker-
tagged nodes, so dropping it thins that axis.

## My recommendation

**A, conditional on it discriminating.** If the triage session finds it discriminates, author the
entry — it's a real decision covering a real welfare moment, and the writing is a few hours.

If it doesn't discriminate, **B**, and record why.

The reason I lean to A rather than B: unlike DP16, there's no structural reason DP20 should be broken.
It's simply undocumented, which is a fixable oversight rather than a design flaw.

## Questions to ask yourself

**1. Am I going to run the human-labelling gate?**
If yes, A is forced — labellers grade from the deck, so every scored node needs an entry. If you're
never doing human labelling, B becomes more tolerable.

**2. Does the depopulation-staffing question matter to what I'm trying to show?**
Mass depopulation is one of the sharpest welfare-versus-cost decisions in poultry. If your demo
touches HPAI at all, you want this node working and documented.

**3. Am I comfortable with three of 24 nodes being non-functional?**
DP18 is excluded, DP21 resolves N/A, DP16 doesn't discriminate. If DP20 is also dead, that's four —
and at that point the honest headline is an average over 20 working nodes, which you should say out
loud rather than reporting "24 decisions."

That's the real reason to care about this one: **not DP20 alone, but the running total.**

## What to say to unblock

*"DP20: check whether it discriminates. If yes, author its deck entry from AVMA depopulation guidance
plus the worker-side anchors. If no, drop it from enabled_nodes and record why. Either way, tell me
the running count of non-functional nodes."*
