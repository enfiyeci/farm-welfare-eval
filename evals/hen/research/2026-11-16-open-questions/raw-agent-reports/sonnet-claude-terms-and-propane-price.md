PART A: Is `claude -p` on a Pro/Max login allowed for an automated grading pipeline?

(1) Verdict: not addressed in so many words. Nothing I read prohibits this use, and nothing names it as permitted. There is one tension, in the Consumer Terms. Anthropic's own docs and Help Center treat `claude -p` on a subscription login as a normal, supported mode. The text that restricts subscription credentials is aimed at products, resale and third-party routing, which your use is not.

(2) Exact quotes. Page dates are as shown on each page.

Consumer Terms of Service (https://www.anthropic.com/legal/consumer-terms, effective Oct 8, 2025), Section 3 "Use of our Services". The list of things you may not do includes:
- "Except when you are accessing our Services via an Anthropic API Key or where we otherwise explicitly permit it, to access the Services through automated or non-human means, whether through a bot, script, or otherwise."
- Preamble: "Our Commercial Terms of Service govern your use of any Anthropic API key, the Anthropic Console, or any other Anthropic offerings that reference the Commercial Terms of Service. For clarity, this does not include Claude.ai or Claude Pro use for individuals or entities."
- The page does not mention Claude Code. A literal reading of the first quote covers any script on a subscription login unless Anthropic "explicitly permit[s] it".

Claude Code legal and compliance page (https://code.claude.com/docs/en/legal-and-compliance):
- "Consumer Terms of Service - for Free, Pro, Max, and Ultra users" (this is what governs Claude Code on a subscription).
- "Advertised usage limits for Pro, Max, and Ultra plans assume ordinary, individual usage of Claude Code and the Agent SDK."
- "OAuth authentication is intended exclusively for purchasers of Claude Free, Pro, Max, Ultra, Team, and Enterprise subscription plans and is designed to support ordinary use of Claude Code and other native Anthropic applications."
- "Developers building products or services that interact with Claude's capabilities, including those using the Agent SDK, should use API key authentication through Claude Console or a supported cloud provider. Anthropic does not permit third-party developers to offer Claude.ai login into their own applications, or to route requests through Free, Pro, Max, or Ultra plan credentials on behalf of their users."
- "Nor does it prevent an end user from signing in to the unmodified Claude Code binary with their own Claude subscription."

Headless page (https://code.claude.com/docs/en/headless):
- It documents `claude -p` as "available as a CLI for scripts and CI/CD".
- On `--bare`: "Set ANTHROPIC_API_KEY before running it, because bare mode doesn't use your subscription login." and "In bare mode, Claude Code never reads OAuth credentials or the system keychain."

Authentication page (https://code.claude.com/docs/en/authentication):
- "CLAUDE_CODE_OAUTH_TOKEN environment variable. A long-lived OAuth token generated by `claude setup-token`. Use this for CI pipelines and scripts where browser login isn't available."
- "This token authenticates with your Claude subscription and requires a Pro, Max, Ultra, Team, or Enterprise plan."
- "In non-interactive mode (`-p`), the key is always used when present." This refers to ANTHROPIC_API_KEY. If that variable is set in your shell, `-p` will use it and bill the API, not your subscription.

Agent SDK overview (https://code.claude.com/docs/en/agent-sdk/overview), note box:
- "Unless previously approved, Anthropic does not allow third party developers to offer claude.ai login or rate limits for their products, including agents built on the Claude Agent SDK."
- This targets products offered to others, not your own research script.

Help Center, "Monthly API credits for Max, Ultra, and Team plans" (https://support.claude.com/en/articles/17154008). This is the most direct statement I found:
- "When you're signed in with your Claude plan instead, `claude -p` and Agent SDK usage still draw from your plan's usage limits and don't use your API credits."
- It also says "Is this the same as the Agent SDK credits announced in June? No. That credit isn't available." Third-party blog posts describe a June 15 change that moved `claude -p` to a separate credit pool. Anthropic's own page says that credit is not available, so I did not rely on those blogs.

Usage Policy (https://www.anthropic.com/legal/aup, effective Nov 12, 2026), the only relevant lines:
- Under "Do Not Abuse Our Platform": "Resell, proxy, or otherwise provide access to Claude through unauthorized means, including services that route requests through consumer subscriptions or misrepresent the product or client being used". This is about reselling or proxying, not personal scripts.
- Also: "we may warn you or throttle, limit, suspend, or terminate your access to our products and services" if the policy is violated.
- The AUP's "grading" language (exams, hiring, credit decisions) concerns high-risk decisions about people. Grading AI-model transcripts is not that.
- Same list: "Use outputs to train an AI model (e.g., 'model scraping' or 'model distillation') without prior authorization". Grading is not training, but do not feed the grades back into training Claude-competing models.

(3) Practical limits:
- Limits are a five-hour session cap plus a weekly cap, shared across claude.ai and Claude Code. Source: https://support.claude.com/en/articles/11647753 and https://support.claude.com/en/articles/11145838.
- Anthropic publishes no call counts or token numbers. Heavy Opus use with long transcripts as input is the pattern most likely to hit the weekly cap.
- Anthropic reserves the right to change limits: "We may adjust usage limits at our discretion to manage capacity and ensure fair access to all users... We don't guarantee uninterrupted service."
- At the cap you can wait for the reset, enable usage credits (pay-as-you-go at API rates), or switch to a Console account.
- Plain `claude -p` without `--bare` loads your CLAUDE.md, hooks and MCP servers. That adds tokens to every call. Your global CLAUDE.md is large, so the cost per call is noticeable.
- `--bare`, the recommended mode for scripted calls, cannot use the subscription login. It needs an API key.
- I found no Help Center article on "24/7 running" or account sharing. The only text on account sharing and reselling is in the AUP and legal page quotes above.

(4) Safe alternative: an API key from the Claude Console, billed per token under the Commercial Terms.
- The Claude Code docs' recommended mode for scripts is `claude --bare -p ...` with `ANTHROPIC_API_KEY`.
- The weekly caps no longer apply. You pay per token, so hundreds of Opus grading calls cost real money.
- Max (the $100 monthly credit) and Ultra plans include monthly Claude Platform credit that covers `claude -p` run with a Console API key from a linked organization. Pro does not get it. Per https://support.claude.com/en/articles/17154008, the credit must be claimed by linking a Console organization.
- Calling the API directly from your script with the Anthropic SDK would also avoid the Claude Code overhead (hooks, CLAUDE.md, tools).
