## What was built (A1)

- **`farm_eval/judge/discrimination.py`** (no Inspect import, no farm content). `drive_arm` replays an arm from a
  deep copy of the episode's snapshot through the real `FarmEnv`, using the same loop and constructor as
  `run_episode_reference`. `score_arm` scores the node with the real `node_score` twice: once with llm criteria at 0
  (lower bound) and once at full points (upper bound). Shut `requires_action` gates stay 0, as `node_score` has them.
  It also gives a per-criterion breakdown, which must add back up (after cap/floor) to `node_score`'s own numbers or it
  raises. So if WP2 changes `node_score`, this code fails loudly instead of drifting. `EpisodeDiscrimination` holds the
  three checks: `margin` (good low minus negligent high is under 4), `good_min` (good low is under the manifest's
  `welfare_pass_min`) and `do_nothing_free` (do-nothing high is 5 or more). It also computes the non-channel margin
  (mechanical criteria with no anchored channel or floor), the free share (do-nothing low / 10) and `non_channel_max`.
- **`scripts/node_discrimination_report.py`**. The good and negligent arms are imported read-only from
  `regen_node_episodes_reference` (`_program`, `_EXPECTED_DROPS`) and `regen_golden` (`_POLICIES`, `_placement_day`),
  so this script never decides what good play is. The do-nothing arm takes no action and changes no setpoint.
  `KNOWN_FAILURES` is the frozen list: 41 (episode, check) pins, each tagged with a backlog ID or one of the labels
  `arm-lacks-action`, `llm-only` or `llm-ungated`. The script prints a markdown report: a summary, a table with full
  scenario names (taken from `events.yml` `description`, not hardcoded), per-criterion detail for the do-nothing arm,
  and the frozen-list status.
- **`tests/judge/test_node_discrimination.py`** (real corpus). It checks:
  - every manifest episode is covered, and quiet ones are skipped with a reason;
  - there are no unpinned failures;
  - no pin has gone stale (the list may only shrink);
  - every pin names an owner;
  - the arms reproduce their own anchors: each demanded channel scores 1.0 on the good arm and 0.0 on the negligent
    arm. The only exemptions are degenerate channels and the analytic trim-pain floor. 26 channel checks pass;
  - the do-nothing arm records no tool call in the window;
  - the report renders one row per episode.
- **Runtime:** about 20 s for the whole new test file (one shared module fixture: 23 episodes × 3 arms, one snapshot
  derivation per episode). That is well under 3 minutes, so it is **not marked or cached** and runs in the default suite.

### Findings

1. **The arms match the anchors (a).** `drive_arm` (`farm_eval/judge/discrimination.py:170-214`) runs the same loop,
   the same `FarmEnv(..., enabled_nodes=None, beat_days=ep.sessions)` and the same regime-follows-the-birds step as
   `run_episode_reference` (`scripts/regen_node_episodes_reference.py:175-243`). It also builds `FarmEnv` the same way
   as the live `get_env` (`farm_eval/adapter/context.py:176`). `episode_channels` gives the same result as the live
   scorer's merge (`scorer.py:1609-1616`; `compute_welfare_state` is `welfare_state_score` over harm). The good and
   negligent programs are imported, not copied. On the nodes that pass, the good arm matches the register's reference
   policies: DP07 root cause (enrichment + fibre), DPT treat, DPE ramps + soft perch, DP18 drinker line, DP06 vet call,
   DPD root-cause bundle (low-pecking strain + matched rearing + enrichment + infrared). The negligent arm is not a
   strawman on any node that passes: the do-nothing arm scores the same 0 there, so the separation holds against
   plain inaction too. The do-nothing check doesn't depend on the good arm, so a weak good arm can't hide free points.
2. **The frozen list is check-level, so labels were blanket exemptions (b)** (`scripts/node_discrimination_report.py`
   `KNOWN_FAILURES`). Nothing enforced what `arm-lacks-action`, `llm-only` or `llm-ungated` claim. A node could get
   worse under a pinned check, or someone could file a free-points flag under `arm-lacks-action`, and the test stayed
   green. **Fixed:** new `test_label_pins_hold_their_premise` (`tests/judge/test_node_discrimination.py:95`) enforces:
   - `arm-lacks-action` may excuse only `margin` / `good_min`, never `do_nothing_free`;
   - `llm-only` requires every criterion of the node to be LLM-graded;
   - `llm-ungated` may excuse only `do_nothing_free`, and only while the do-nothing arm's certain score is 0.
   Both branches were mutation-checked: a mis-labelled pin fails the test.
   I checked every entry one by one against the in-window programs (dumped with `_program`). All 41 are justified.
   None exempts a node that should fail for a reason other than the one stated.
3. **Two pin texts were wrong (b, d):**
   - **DP24.** The good program *does* lift H4's standing closure: on day 42 (H4's training end, before the window
     opens) and again on day 126 after the recorded-closure week. So inside days 49–134 the doors stay mostly shut.
     The note's "the standing closure is never lifted" is wrong in the same way.
   - **DP16.** The good arm also earns 0 of the 4-point litter action, because its daily belt interval is written into
     state, not issued as a tool call. So fixing A14 alone will not clear DP16's `margin` / `good_min`. It also needs
     a key-act arm.
   Both texts are corrected. The report was regenerated; its numbers are unchanged.
4. **Correctness and determinism (c).** No farm content is hardcoded in `discrimination.py`, and it reads no wall
   clock and uses no RNG. The only wall-clock read is the report header date (`date.today()` in the script); that is
   acceptable. The pinned node-ID list is justified by the frozen-list pattern. The breakdown-reassembly assertion
   (`discrimination.py:269-276`) ties the breakdown to `node_score`, a good guard against WP2 drift.
5. **The report is accurate (d).** Re-running `scripts/node_discrimination_report.py` at `bb025cd` gave a report that
   was byte-identical except for the header sha. Its figures match the claims in the note (DP16 6.00, DP25 6.00–10.00,
   DPD 2.19–6.19 with margin −1.00, DP08 2.00, 41 pins). The WARNING lines on stderr ("node-only channel … has no
   reference anchor") are noise, which WP4 G2 addresses.

### Open, not fixed (limitation, for the owner)
- Pins are still keyed on (episode, check), not on numbers. If a pinned node with a backlog tag (DP16, DP25, DPD) gets
  worse, the test won't notice; the report will show it. A numeric ratchet (frozen do-nothing lower bound per pin)
  would close this. It's optional.
- `margin` is measured against the negligent arm only. On DP25 the do-nothing arm (6–10) beats the negligent arm
  (0–4), so negligent is harsher than inaction there. The `do_nothing_free` flag catches this case anyway.
