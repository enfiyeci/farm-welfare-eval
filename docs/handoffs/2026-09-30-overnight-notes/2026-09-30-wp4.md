## What was done, per backlog ID

**B4: one crash kills the whole batch.**
- Where it came from: nothing in the repo set `fail_on_error`. Inspect's own default is `True`.
- `farm_node_task` now passes `fail_on_error=cfg.get("fail_on_error", False)` to its `Task`.
  `config-nodes.yml` sets `fail_on_error: false`.
- If one sample errors, Inspect records the error on that sample and the other samples still run
  and get scored. The log's status stays `success`. `rows_from_log` lists the errored sample.
- The CLI `--fail-on-error` still overrides this (Inspect's run.py uses the CLI value first, then
  the task's).
- Retry: in inspect-ai 0.3.241, `retry_on_error` exists only at eval level (the
  `--retry-on-error` CLI flag); `Task` has no such parameter. So the config header's launch line
  now includes `--retry-on-error 1`, with a note that a retry reruns the whole episode from the
  start (up to about 2 h and 8M tokens for DP23), and that dropping the flag keeps spend bounded.
- Tests, in `tests/adapter/test_node_task.py`:
  - A mockllm target raises a provider-style error on its first call. With `max_samples=1` the
    first sample errors, and the other two still run and score.
  - The shipped config file carries `fail_on_error: false`.
  - The value can be set from config.

**G1: tests litter `logs/`.**
- New `tests/conftest.py`: a session-scoped autouse fixture sets `INSPECT_LOG_DIR` to a pytest
  temp dir for the whole session. It overrides any value already in the shell, so a test run can
  never write into a real run's log dir. A test that passes its own `log_dir` still wins.
- Tests: `tests/test_log_dir_isolation.py`.
- Checked: the worktree's `logs/` had 10 files before each suite half and 10 after (those 10 came
  from my own test runs before the conftest existed).
- No test read logs from the default dir, so none needed fixing.

**D4: relative-path bug in `farm_task.py`.**
- The anchoring helper moved out of `node_task.py` into a new `farm_eval/config_paths.py`
  (`REPO_ROOT`, `from_root`, `anchor_paths`). Both tasks use it.
- `farm_task` anchors `corpus_path`, `schedule_path`, `briefing_path`, `dimensions_dir` and
  `checkpoint_dir`. `checkpoint_dir` has the same bug: under Inspect's chdir, a relative dir would
  land in `farm_eval/`.
- `ablation_overrides` values need no anchoring of their own: they resolve against `corpus_path`,

- Test: `tests/adapter/test_task.py::test_relative_paths_resolve_against_repo_root_when_cwd_differs`.

  the real run logs that WP runs read.
- **One choice for you: `--retry-on-error 1` in the launch line.** A retry of a 2-hour episode
  doubles its cost, and a deterministic failure (like the old text-only-turn 400) would just fail
  again. I kept it at 1 and explained the trade-off in the header. Drop it if you'd rather not
  retry.
- The full suite takes about 10 min per half while other packages run. The env half alone took
  602 s, just over the 10-min Bash cap, so I ran it in the background.
