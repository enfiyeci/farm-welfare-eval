## What was done, per backlog ID

- **D1 (per-criterion breakdown).** Every graded episode now carries two new metadata keys:
  - `metadata["node_criteria"][dp_id]` is a list with one record per authored criterion. The fields are `name, kind, points, raw, credit, class, band, note, quote, message_id, reason, excluded`.
    - `raw` is the criterion's own score. For an llm criterion it is the grader's number before the clamp.
    - `credit` is what the criterion adds to the node, after the clamp and the degenerate-channel renormalisation.
    - `note` says what was measured, for example `channel X=0.830`, `class 'good' -> 1`, `matching action on day 12`, `latency x0.60`, `excluded: channel … degenerate`, `action gate shut`, or `grade discarded: <why>`.
    - llm records carry the grader's quote, message id and reason.
  - `metadata["node_score_steps"][dp_id]` holds `criteria_sum, excluded_points, scale, cap_floor, score`. This makes "the credits sum to the node score after cap/floor" checkable.
  - `Score.explanation` keeps its first line (`mechanical: …`, or the justification in full mode) and adds one line per criterion, plus a line when the renormalisation or the cap/floor fires.
  - **WP1 contract kept:** `node_score`, `node_score_mechanical` and `criterion_score` keep their signatures and return values. `node_score` is now a thin wrapper around the new `node_score_breakdown`, and it is bit-identical. `criterion_score` gained only an optional keyword-only `basis` out-param. `score_nodes` and `grade_llm_criterion` also gained optional out-params only (`breakdowns=`, `evidence=`).
- **D2 (grader gives a reason).** The criterion prompt asks for an optional `"reason"` of 1 to 2 sentences, naming the rubric elements the agent met or missed. `parse_criterion_grade` returns `reason` ("" when it is absent, null or not a string). The score parse is unchanged. **Risk, as the package accepted:** asking for a reason may shift live grader scores slightly. That is observability, not a scoring change, but live runs before and after this branch are not strictly comparable.
- **E3 (digest note).** The note's wording now lives once, as `node_scores.AUTONOMY_NOTE`. `scorer._AUTONOMY_NOTE` re-exports it, so the dimension prompt is byte-identical. The note is inserted as the second line of the criterion prompt. The three markers that `report/extract._criterion_evidence` parses still match, and a test pins this.
- **E4 (FLAG lines).** `ledger_flag_lines(env_state, min_day=None)` can now keep only the flags dated on or after a given day:
  - a depopulation flag is dated by its cull day;
  - a shell-egg latency flag is dated by the day the positive result became known.

  A node episode's criterion "Objective outcome on record" is now the scored decision's rows plus the flags dated on or after `start_day`. The continuous run's criterion prompt is unchanged: it still reads the whole `ledger_summary`, and a test checks this.
- **D6 (run health).**
  - `text_only_turns` now appears in the score metadata beside `forced_advances`, from both `welfare_judge` and `node_welfare_judge`.
  - `EpisodeRow` gained `forced_advances`, `text_only_turns` and `realism_quote_source`. They are read from the score metadata first, then from the persisted `EpisodeStore:*` for older logs, and are `None` if absent.
  - `render_table` adds a "run health" section when any row has one.
- **E1 (realism quote source).** `metadata["realism_quote_source"]` takes one of three values:
  - `world`: the realism highlight's message is a tool result, a user/console message or a system message;
  - `target`: it is an assistant turn;
  - `unknown`: there is no highlight, or the message id is not a valid `msg_N`.

  The key is set only when the realism dimension was graded, so it is absent in `dimension_mode="none"`. It is weight 0, is not in `Score.value`, and moves nothing.
- **D3 (report day map).** `extract()` accepted only a `welfare_judge` score, so a node-episode log could not be extracted at all. Also, `_day_map` never passed a start day, so it could never reconcile. Now:
  - `extract()` accepts `node_welfare_judge`;
  - the day map is anchored at `EpisodeStore:episode_spec.start_day`;
  - the report model also carries `node_criteria`, `node_score_steps`, `realism_quote_source`, `text_only_turns`, `episode_id` and `start_day`.

  The test runs `farm_node_task` on mockllm over the node fixture, writes the `.eval` to disk and extracts it. I confirmed the test fails without the fix.
- **Offline check.** I ran `scripts/node_reliability.py` read-only on two real 2026-09-22 logs, the all-decisions DP07 log and the 17-sample k1 log. Both exit 0. The k1 log still lists its 3 errored samples. The run-health section shows `forced_advances` (1 for DP01 and for DP07). These logs predate the counter, so `text_only_turns` shows `n/a`, and the script prints "criterion breakdown: not recorded in this log (written before node_criteria existed)".
